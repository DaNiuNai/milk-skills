# GPT Image 防碎图指南

> 适用于 GPT Image 2 / ChatGPT Images 的生成与编辑。

## 0. 核心结论

“碎图”是六类不同的故障，不能靠一条万能负面词解决。能做的只有三件事：

1. **生成前**：用清晰的空间结构和细节分层，降低触发概率。
2. **生成后**：查看原始成品，尽早拒收坏图。
3. **失败后**：从干净状态按恢复阶梯处理，每次只改一个变量。

模型自身产生的纹理噪声只能缓解，无法保证根治。

---

## 1. 速查清单

**生成前**

- [ ] 写明“**一张完整、连续的单场景画面；同一空间、同一时刻、同一摄影机视角**”（确实需要拼贴、分镜或角色表时除外）。
- [ ] 只设**一个主焦点、一个主动作、一个主光源**。
- [ ] 写出主体的**精确数量**，并说明位置、相对尺度、前后遮挡和接触点。
- [ ] 细节分层：焦点区域高细节，次要区域中等细节，背景用大块、连续、安静的形状。
- [ ] 删掉“到处超精细 / maximalist / countless tiny details / overloaded”这类全局密度词（用户明确要求时除外）。
- [ ] 不要同时堆叠透明、发光、反射、雾化、颗粒、裂纹等多种复合材质，只保留真正服务主题的。
- [ ] 排除项只写 **3–8 条**与当前风险直接相关的内容，不贴 Stable Diffusion 式的长负面词表。
- [ ] 需要多个方案时，**每张图单独生成一次**，不要塞进同一张画布。
- [ ] 编辑时**每轮只改一处**，并重申不变的内容。

**生成后**

- [ ] 打开**原始成品文件**，放大到 100%–200%，按第 6 节逐项检查。

**失败后**

- [ ] 每次只改一个变量。
- [ ] 出现全局碎纹时**不要继续编辑坏图**，应回到最后一张干净图或从头生成。

---

## 2. 先判断是哪种碎图

| 类型 | 典型表现 |
|---|---|
| 传输或中间态错误 | 文件截断、解码失败；API 把流式 `partial_image` 当成了最终图 |
| 全局纹理破碎 | 蜂窝、棋盘格、斜网格、彩色碎屑、脏噪点、重复微纹理、过度锐化 |
| 版式破碎 | 要的是单幅画面，却得到拼贴、分屏、多格漫画、角色表、信息图或随机边框 |
| 空间或材质破碎 | 背景不连续、物体粘连、漂浮碎片、边界融化、透视或光源互相冲突 |
| 解剖或动作破碎 | 肢体多了或少了、左右互换、人物融合、接触点断开、遮挡关系不可能成立 |
| 编辑或上下文漂移 | 未编辑区域被改动、旧图元素像幽灵一样残留、越迭代越脏 |

**无法确定类型时**，不要猜测模型内部原因。先确认看的是原始成品文件，并检查实际发给模型的最终提示；然后分别做一次“简化提示”测试和一次“新会话”测试（见 7.3）。

---

## 3. 五条工作原则

1. 保留原有的主题、风格和用途，不擅自删掉核心创意。
2. **先确定几何和空间，再分配细节**；细节不要平均铺满整张图。
3. 排除项要少，并且只针对当前风险。
4. **生成后必须看图验收**，提示词写得对不代表输出合格。
5. 已经出现全局碎纹、蜂窝或网格的图片，**不要反复递归编辑**。

## 4. 写提示：连贯性规格

复杂请求按下面的顺序组织，用短标签或换行分隔，**只保留用得上的字段**：

```text
用途：<成品将用于哪里>
画面承诺：一张完整连续的画面；<一个场景、同一时刻、同一摄影机视角>
场景：<地点与前景/中景/背景>
主体：<精确数量、身份、外观；一个主要焦点>
空间关系：<各主体位置、相对尺度、前后遮挡、接触点>
动作：<每个主体一个清晰动作；视线与手脚关系>
镜头与构图：<景别、视角、透视、完整入镜范围、留白>
材质与细节层级：<焦点高细节，次要区域中等，背景受控>
光照：<一个主光源、方向、色温、阴影>
风格/媒介：<一个主媒介和相容的风格族>
必须保持：<编辑或参考图中的不变量>
排除：<只列与当前风险直接相关的 3–8 项>
```

原提示已经很具体时，只做重排和消歧，**不要另加**人物、道具、品牌、情节或没要求的左右布局。

### 4.1 连续画面（防拼贴）

```text
一张完整、连续的单场景画面；同一空间、同一时刻、同一摄影机视角。
没有拼贴、分屏、多面板、角色表、接触表、随机边框或互不连通的小场景。
```

容易触发拼贴的说法有：“多个方案”“不同视角”“before/after”“reference sheet”。遇到这类需求，应拆成多张独立的图分别生成。

### 4.2 复杂度预算

- 用正向的结构描述代替堆砌细节，例如：**连续表面、清晰材质边界、轮廓分离、受控细节密度、统一透视和色温**。
- 精细纹理集中在焦点上，次要区域减少微细节，背景用大块、连续的形状。
- 提示长本身不是问题。真正的问题是：对象关系不清、细节互相冲突，或细节量超出画面能承载的范围。

### 4.3 人物、动物与复杂动作

- 写出精确的主体数量，每个主体只做一个能看清的动作。
- 写明全身还是半身、脚是否入镜、**人物自身的左右**（不是画面的左右）、哪只手接触哪个物体、哪只脚承重。
- 写清前后关系、遮挡和接触点。多个主体时让轮廓错开，避免身体大面积重叠。
- 复杂姿势可以配一张轮廓清楚的姿势参考图。
- 精灵帧、转面图、动作序列要**逐帧生成**，再用程序拼接，不要让模型一次画完整张 sheet。
- 用几何关系描述代替一长串 `bad anatomy, extra limbs...`。

### 4.4 参考图与编辑

- 只用完成任务所必需、本身没有碎纹的干净参考图。
- 参考图按 `Image 1`、`Image 2` 编号，每张图只承担一项明确职责（底图 / 主体 / 姿势 / 服装 / 风格 / 背景）。
- 写明从哪张图取什么、放到哪里、哪些内容绝对不要复制。
- 合成时统一尺度、透视、光照方向、色温、遮挡和接触阴影。
- 每轮只做一个主要改动，并重申身份、几何、镜头、背景、未编辑区域等不变量。
- **每次编辑成功后保存一个干净的检查点**。Mask 只是软约束，仍需检查选区外有没有变化。

## 5. 生成设置

### 内置图像工具（如 ChatGPT）

- 不要假设存在工具没有提供的 `quality`、`size`、seed、CFG 等参数。
- 多张独立成品分多次调用生成。
- 编辑本地图片前，先确认原图本身没问题。
- 验收时看实际成品，不要拿模糊的预览图代替。

### `gpt-image-2` API

| 项目 | 建议 |
|---|---|
| 尺寸 | 排障时先用常规尺寸：`1024x1024`、`1536x1024`、`1024x1536` |
| 超高分辨率 | 总像素超过 `2560x1440` 时输出更不稳定，不要从这类尺寸开始排查问题 |
| quality | `low` 用于草稿；人物、密集细节、对身份敏感的编辑或最终资产，对比 `medium` 和 `high` 再选。高质量档不能修好所有结构错误 |
| `input_fidelity` | 对 `gpt-image-2` **不要传**，模型会自动按高保真处理输入图 |
| 流式输出 | 只把 `completed` 或最终事件保存为成品，`partial_image` 只用于预览 |
| `revised_prompt` | 记录并检查。如果改写后出现了多场景、面板、海报或没要求的对象，先修正提示再重试 |
| 模型快照 | 可以锁定快照做回归测试，但快照**不等于**固定 seed，也不能保证逐像素复现 |

## 6. 生成后验收

查看原始输出，必要时放大到 100%–200%：

1. **整体**：是否为一张连续画面；主体数量、主焦点和故事时刻是否正确。
2. **空间**：地平线、透视、前中后景、遮挡、接触点、阴影和光源是否一致。
3. **轮廓与解剖**：头、躯干、四肢、手脚、尾巴、翅膀的数量是否正确，连接是否连续。
4. **纹理**：天空、皮肤、雾、水、毛发、树叶和暗部有没有蜂窝、棋盘格、重复碎块或脏噪点。
5. **边界**：有没有随机接缝、边框、局部贴片、材质融合或漂浮碎片。
6. **编辑不变量**：选区外的内容、人物身份、镜头、背景是否保持不变，有没有多出没要求的内容。

**以下情况直接判为失败**：主体数量不对、画面不连续、明显的解剖错误、全局碎纹、破坏了编辑不变量。不要因为配色好看就接受。

质检记录模板：

```text
输出编号：
使用提示：
生成路径：内置工具 / API
文件状态：最终成品 / 中间态不确定

整体连续性：通过 / 失败 — <证据>
主体和解剖：通过 / 失败 — <证据>
空间与接触：通过 / 失败 — <证据>
全局纹理：通过 / 失败 — <证据>
编辑不变量：通过 / 失败 / 不适用 — <证据>

判定：接受 / 有限修复 / 从头重生 / 模型侧限制候选
下一次只改变：<一个变量>
```

## 7. 失败后怎么恢复

### 7.1 恢复阶梯（每次只改一个主要变量）

| 情况 | 动作 |
|---|---|
| 1. 偶发、零散的小错误 | 提示不变，重试一次；问题依旧就进入下一级 |
| 2. 布局、空间或解剖错误 | 补全数量、位置、遮挡、接触和镜头关系，减少主体重叠后重新生成 |
| 3. 全局碎纹或材质融合 | 减少主体、微纹理和复合材质，改用分层细节，**从头生成**，不要在坏图上继续编辑 |
| 4. 越迭代越差，或卡在拼贴 / 信息图版式 | 回到干净检查点；必要时把完整提示精简后在**新会话**里重来（这是经验做法，不是官方保证） |
| 5. 局部编辑导致大范围变化 | 回退到检查点，缩小单次改动；小瑕疵优先用确定性的修图工具处理 |
| 6. 同一种全局噪声反复出现 | 停止叠加提示词，按模型侧限制处理；保留干净提示和失败样本，用于回归测试 |

### 7.2 症状对照表

| 症状 | 先排查 | 首选动作 | 不要做 |
|---|---|---|---|
| 文件打不开、只有部分内容、像没画完 | 文件长度、格式、流式事件类型 | 重新获取 `completed` 或最终事件，并验证文件 | 试图用提示词解决文件传输问题 |
| 整张图布满蜂窝、棋盘格或重复碎纹 | 原始 PNG 和截图是否一样 | 降低细节密度和复合材质，从干净状态重新生成 | 相信某条负面词能根治 |
| 单幅图变成拼贴、分屏、角色表或信息图 | 最终提示或改写后的提示是否含多场景、sheet 类说法 | 拆成多条独立提示分别生成，并写明单一连续画面 | 在同一个坏会话里不停追加 `no collage` |
| 主体粘连、漂浮碎片、背景断层 | 位置、尺度、透视、光源、材质边界是否写明 | 写清空间关系，统一主光和透视，减少复合材质 | 只加“高清、细节丰富” |
| 肢体多了、左右错位、接触点断开 | 主体数量、人物自身左右、承重脚、遮挡 | 错开轮廓，每人一个动作，写清接触和前后关系 | 粘贴几十条解剖负面词 |
| 局部编辑后整图变了，或出现接缝 | 是否从干净检查点开始、每轮是否只改一处 | 回退检查点，缩小单次改动，重申不变量 | 在已经变化的结果上继续修补 |
| 旧图元素残留，或同一会话越来越脏 | 对比新提示和新会话的结果 | 把完整提示精简后，在干净的上下文里重新生成 | 认定“开新会话”一定有效 |

### 7.3 来源不明时做三组对照

1. **文件对照**：确认看的是最终原始文件，不是流式中间图、缩略图或高压缩截图。
2. **提示对照**：保留主题和主风格，只去掉微细节、复合材质和多重动作，用标准尺寸生成一张。
3. **状态对照**：在干净的上下文里，用同一份精简提示再生成一次。

结果怎么看：

- 只有文件对照有问题 → 先修 API 或保存流程。
- 简化提示后明显变好 → 复杂度和关系描述是主要可控因素。
- 换新上下文后明显变好 → 可能是上下文污染（经验判断），保存一个最小复现样本。
- 三组都出现同样的全局碎纹 → 按模型侧限制处理，停止无休止地重试。

### 7.4 重试上限

- 偶发错误：原提示最多重试 **1 次**。
- 已定位的结构问题：最多针对性重写 **1 次**再生成。
- 全局纹理噪声：降低复杂度后重新生成 **1 次**，仍失败就按模型限制处理。
- 想继续探索可以加轮次，但每轮都要记录改了哪个变量和验收结果。

## 8. 可复制模板

模板只是骨架，用得上的字段填，用不上的删掉。

### 8.1 单场景生成

```text
用途：<用途>
画面承诺：一张完整、连续的单场景画面；同一空间、同一时刻、同一摄影机视角。

场景：<地点>。前景为 <...>，中景为 <...>，背景为 <...>。
主体：画面中恰好有 <数量> 个主体：<逐一描述>。主要焦点是 <主体>。
空间关系：<主体 A> 位于 <位置>，比 <主体 B> <大/小/近/远>；<遮挡和接触关系>。
动作：<每个主体一个清晰动作>。
镜头：<景别、视角、透视、完整入镜范围>。
材质与细节：焦点区域 <高细节>；次要区域 <中等细节>；背景使用较大连续形状和受控细节密度。
光照：一个主要光源来自 <方向>，统一 <色温>，所有接触阴影与之匹配。
风格：<一个主媒介和相容风格>。

约束：所有主体共享同一地面、透视、光源和色温；轮廓连续，材质边界清晰。
排除：没有拼贴、分屏、多面板、随机边框、重复主体、漂浮碎片或画面接缝。
```

### 8.2 多人物或动物

```text
主体数量：恰好 <N> 个，分别为 A、B、C。
A：位于 <位置/景深>，<动作>，<哪只手/脚> 与 <对象> 接触。
B：位于 <位置/景深>，<动作>，轮廓与 A <不重叠/只在某处自然遮挡>。
C：<同上>。

身体关系：每个主体只有一颗头和一具连续身体；肢体从正确关节连接。
人物自身左/右：<明确说明>。
承重与接触：<哪只脚着地、重心、手抓握、物体支撑>。
取景：<全身/膝上/半身>，<脚/手> 完整入镜。
```

### 8.3 细节密集的幻想或自然场景

```text
主要焦点：<唯一焦点>，清晰轮廓，承担最高细节。
次要元素：最多 <数量> 类，使用中等细节，不与焦点轮廓融合。
背景：使用大块、连续、安静的形状；只保留少量可读纹理。
材质边界：石头、植物、水、雾和发光元素保持清晰分区，不互相熔化。
光照：只有一个主光方向；发光物仅作局部辅光。
细节层级：细节集中于焦点，画面边缘和背景逐渐简化；不要全局微细节、重复纹样或过度锐化。
```

### 8.4 参考图生成或合成

```text
Image 1：底图，只提供场景、镜头和构图。
Image 2：主体参考，只提供身份、服装和外观。
Image 3：姿势参考，只提供身体姿态，不提供身份、服装或背景。

任务：把 Image 2 的主体放入 Image 1 的 <具体位置>，采用 Image 3 的姿势。
匹配：Image 1 的尺度、透视、光照方向、色温、遮挡和接触阴影。
保持：Image 1 的镜头、背景和未编辑对象；Image 2 的身份和比例。
不要复制：<每张参考中不应进入结果的内容>。
```

没用到的参考图对应的行直接删掉。参考图越多，各自的职责越要互不重叠、写得清楚。

### 8.5 单变量编辑

```text
只修改：<一个目标区域或属性>。
具体变化：<目标结果>。
必须保持：人物身份、身体比例、姿势、镜头、透视、构图、背景、光照、色温、未编辑对象和原始画质不变。
融合要求：边缘连续；材质、噪声尺度、光照和阴影与原图一致；没有贴片感或接缝。
不要添加：新人物、新物体、文字、标志、边框或未要求的装饰。
```

## 9. 两个高风险请求示例

### 示例 1：细节密集的外星丛林（竖版写实奇幻）

原始需求：暴雨后的外星丛林里，一名穿透明雨披的植物学家手持半透明发光孢子球，周围有湿润树叶、细密藤蔓、反光水洼、荧光蘑菇、漂浮花粉、薄雾、远处瀑布和许多微小外星生物，要求“极致复杂、到处都有超精细纹理”、强反射、体积光。

- **风险点**：全局密度词；透明、半透明、发光、反射、雾、粒子多种复合材质叠加；次要元素很多。
- **处理方向**：保留核心创意；焦点只放在植物学家和孢子球上；细节分层；材质边界连续；统一光照。
- **合格标准**：
  - 单幅连续画面，没有拼贴、分屏或互不连通的小场景。
  - 只有一名植物学家，身体连续，没有重复、漂浮或断开的部位。
  - 孢子球数量明确，与手有可信的接触，既不悬空也不和身体融在一起。
  - 人物、近景植物、水洼、雾、瀑布和发光元素的透视、空间层次和主光方向一致。
  - 放大到 100%–200% 时，整图没有蜂窝、棋盘格、重复块状纹理或脏噪点。
  - 细节集中在人物和孢子球上，背景是可读的大形状，材质边界清晰。

### 示例 2：三名工人搬沙发过门（横版纪实）

原始需求：三名搬家工人把大沙发搬过狭窄的公寓门口，一人在门内后退拉扶手，一人在门外抬另一端，一人侧身托住中部；三人全身可见，手脚与沙发的接触要准确。

- **风险点**：多人、全身、接触关系复杂，窄门造成遮挡。
- **处理方向**：写明恰好三人；每人一个动作；写清接触点、承重关系和前后遮挡。
- **合格标准**：
  - 单幅连续的门口场景，没有拼贴、分屏或边框。
  - 恰好三名工人和一张沙发，没有重复人物、多余半身或融合的主体。
  - 每人各有一颗头、一具连续躯干、两条手臂和两条腿，没有多余、缺失、断开或左右互换的肢体。
  - 拉、抬、托三个动作分工正确，关键部位的手与沙发接触可信。
  - 沙发、门框和三人的透视、承重、地面关系和接触阴影一致。
  - 放大到 100%–200% 时，没有蜂窝、棋盘格、接缝或脏噪点。

## 10. 边界：官方事实、经验做法和不能声称的内容

### 官方可验证的事实

1. `gpt-image-2` 支持生成和编辑、灵活尺寸和高保真图像输入，并提供固定的模型快照。—— [模型页](https://developers.openai.com/api/docs/models/gpt-image-2)
2. 官方列出的已知限制：多次生成之间的视觉一致性偶尔不稳定；结构化或对布局敏感的构图难以精确摆放。—— [图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)
3. 官方建议复杂提示按“场景/背景 → 主体 → 细节 → 约束”组织；明确构图、视角、人物尺度、姿态和互动；多张参考图逐张编号；小步迭代、每次只改一个变量。—— [提示指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)
4. 总像素超过 `2560x1440` 属于实验范围，输出更不稳定；`low` 适合草稿，复杂的最终资产应比较 `medium` 和 `high`。
5. 对 `gpt-image-2` 不要传 `input_fidelity`，输入图会自动按高保真处理。
6. Mask 是由提示驱动的软约束，不保证严格贴合形状；有多张输入图时，mask 只作用于第一张。
7. 流式 API 会先发部分图像，再发完成事件，只有最终的完成事件才应保存为成品。
8. Responses API 的图像工具可能改写提示，并返回 `revised_prompt` 供检查。

（4–8 均出自同一份图像生成指南。）

### 经验做法（不是官方保证）

- “单一连续画面、同一空间、同一时刻、同一镜头”这句约束是根据官方构图原则设计的，不保证一定生效。
- 减少微细节、复合材质和主体重叠，是降低复杂度的保守做法，官方并未证明它能消除所有全局纹理伪影。
- 只用必要的参考图，是为了避免职责冲突，并不是参考图越少越好。
- 开新会话可以作为诊断对照，不是官方的修复步骤。
- 从最后一张干净检查点恢复、不把坏图反复喂回模型，是一种生产流程上的风险控制。

### 不要相信或声称

- 蜂窝、棋盘格或碎纹一定是隐藏水印造成的。
- 所有碎图都是因为提示写得太长。
- 固定模型快照就等于固定 seed，或者能逐像素复现。
- Mask 能保护选区外的每一个像素。
- 某个负面词、固定的重试次数或 high quality 能根治碎图。
- 官方已经彻底修复了模型侧的伪影。
